# Template — Layer 1 concept page

Per-concept page generated by Ingest (Workflow 3). Lives at
`01-canonical/concepts/{{SLUG}}.md`. One concept per file, no
exceptions.

The slug is the filename without `.md`, lowercase, hyphenated.
Examples: `contribution-margin-1`, `bill-rate`, `good-leaver-clause`,
`double-materiality`.

Section headings below are English by default. If `CLAUDE.md`
section 3 declares the case is in another language, translate the
headings consistently across all concept pages and use the
translated form thereafter.

## Frontmatter notes

- `kind: concept` — always literal. Distinguishes concept pages
  from entity pages (`kind: entity`), skeleton files, source
  summaries, log entries, derived artifacts, and lint reports. If
  this page is about a named real-world thing that *acts* (person,
  firm, system, regulator), use `kind: entity` and
  `templates/entity-template.md` instead — see "What goes to
  `entities/`" below.
- `first_seen` — the date this concept first entered the Cortex.
  Do not update this when the page is edited; that's what the
  Change Log is for.
- `sources` — list of pointer IDs the concept derives from. Add to
  the list when later ingests touch the same concept; do not
  replace.
- `aliases` — alternative names, abbreviations, or competing
  terms. Lint uses this to detect duplicate concept pages.
- `confidentiality` — propagated from the source. Concept pages
  inherit the strictest confidentiality of any source they touch.

## Sectioning rules

- **Definition is short and source-anchored.** If the source spells
  out a definition, quote or closely paraphrase it. If it doesn't,
  mark the Definition as a TODO and put what you can in
  Description.
- **Description is long and rich.** This section is the point of
  the concept page. Aim for 3–10 sentences. Mark synthesis
  explicitly with `> Synthesis:` blocks if you go beyond what the
  source states. An empty Description triggers a lint warning.
- **Related concepts and entities is mandatory in spirit.** A
  concept with no outgoing links is suspect — either the
  enumeration missed its neighbours, the concept is mis-scoped, or
  it should be an entity. Aim for 1–5 outgoing links combined
  (other concepts and/or the entities the concept applies to or
  constrains).
- **Open questions** is the local home for concept-specific gaps.
  If a question affects the case broadly, mirror it to
  `02-working-memory/open-questions.md`.
- **Trade-offs is expected for design-bearing concepts.** Any
  concept that names a mechanism, calibration, clause, or
  allocation rule has trade-offs by definition — the design space
  had alternatives, and one was chosen. Naming the trade-offs
  makes the design choice visible and re-litigable. Pure
  descriptive concepts (e.g. a KPI definition that the business
  simply *uses*) may legitimately have no trade-offs to list — in
  that case, omit the section. Lint flags missing Trade-offs on
  clearly design-bearing concepts as a nit.
- **Synthesis is optional but encouraged.** When you notice
  patterns the source doesn't state, name them here. Mark them
  clearly so a future reader can tell synthesis from
  source-grounded fact.
- **Change Log is mandatory.** Append-only. One line per change.

## When to create a concept page

Concept pages describe **how something works** — mechanisms, not
agents. Anything in this list deserves its own concept page:

- A KPI or metric with a definition
- A formula, calculation, or allocation rule
- A workflow, process, or decision rule
- An abbreviation or term-of-art with case-specific meaning
- A policy, standard, regulation type, or contract clause
- A load-bearing relationship between other concepts
- A regime, doctrine, or methodology

If you're unsure whether something is a concept, apply the
**phone-call test**: *can this thing make a phone call?* If yes
(or if it acts in the world with a name), it's an **entity** —
create `01-canonical/entities/{{SLUG}}.md` from
`templates/entity-template.md` instead. Mis-routed pages are
cheap to fix later; lint catches them.

If you're still unsure whether something deserves *any* page,
create the page in the directory it best fits. Lint will flag
mis-routed pages and orphans later, and you can merge, move, or
delete then. Erring on the side of more pages is the default.

---

## What goes to `entities/` instead of `concepts/`

Named real-world things with identity that *act* in the case. Move
these (or create them directly under `entities/`):

- **Persons** — individuals with a role on the case.
- **Organisations / legal entities** — firms, agencies, named
  teams, specific legal entities by full name, suppliers, peer
  comparators.
- **Products / systems** — named software, named contracts, named
  datasets, named tenders, named programmes.
- **Regulators / jurisdictions** — when the named regulator's
  identity matters (a specific regulatory body by name — not
  generic "the regulator"). Note: the *regime* the regulator
  issues stays as a concept; the *regulator* itself is an entity.
  Cross-link them.

If you find a page in `concepts/` that is actually about a named
acting thing, move it to `entities/{{SLUG}}.md`, swap to
`entity-template.md`, and update inbound links. Lint flags this as
a warning.

---

## When NOT to create a concept page

- One-off facts that aren't named or referenced elsewhere
- Synonyms of an existing concept (use `aliases` frontmatter
  instead)
- Named real-world things (those go to `entities/` — see above)
- Meeting notes, decisions, or events (those are Layer 2)
- Generated outputs (those are Layer 3)
- Pointers to external resources (those are Layer 4)
